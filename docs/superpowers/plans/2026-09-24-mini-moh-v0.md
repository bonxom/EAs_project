# Mini-MoH v0 Implementation Plan

Execution status: completed on 2026-09-24. See [implementation and validation record](../2026-09-24-mini-moh-implementation.md) for review fixes, decisions, and limits. Planning-time repository notes below are historical.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build a reproducible, offline-testable two-level search for TSP heuristic programs, with constrained optimizer evolution, subprocess execution, and complete experiment records.

**Architecture:** `HeuristicOptimizer` searches Python heuristic sources; `MetaOptimizer` searches validated `OptimizerSpec` values. `OptimizerEvaluator` compares optimizers on fixed tasks with fresh inner populations, while a trusted parent scores tours returned by disposable workers. `LLMClient` supplies text to either search level and is never an optimizer.

**Tech Stack:** Python 3.12, uv, NumPy, Pydantic, PyYAML, OpenAI SDK confined to its adapter, pytest, pytest-cov, Ruff, subprocesses, YAML configuration, strict JSON/JSONL records.

**Spec:** [Mini-MoH v0 specification](../specs/2026-09-23-mini-moh-design.md). Read it together with `AGENTS.md`. The older `docs/moh_codex_project_plan.md` provides background; the newer spec resolves its conflicts.

## Global Constraints

- Python 3.12.
- Use uv.
- All experiments must be reproducible with seeds.
- Unit tests must never call external LLM APIs.
- FakeLLM is mandatory for tests.
- Never execute generated code in the main process.
- Generated programs must have timeouts.
- Failure of one generated candidate must not crash an experiment.
- Keep core abstractions provider-independent.
- Do not hardcode OpenAI-specific logic outside llm/openai_client.py.
- Default limits: 64 KiB source, 1 MiB result, 64 KiB captured output, and five seconds per instance.
- Use one canonical field name, `use_reflection`, resolving the roadmap's inconsistent naming.
- Failed utility is JSON null, with status determining its bottom rank; do not serialize Infinity or NaN or average a numeric failure sentinel.
- Smoke defaults: seed 42; two outer iterations; outer capacity two; two inner iterations; initial inner capacity three; TSP sizes 10 and 20; three instances per task; fake provider.
- Zero search iterations are permitted and return evaluated seed populations.

## Review Focus

1. A worker mutates coordinates or its unvisited list: parent scoring still uses original coordinates and validates the complete tour (Tasks 3–4).
2. A worker prints forever, exits abruptly, or leaves a descendant holding a pipe open: byte limits and wall-clock deadlines still bound the evaluation and all worker processes are reaped (Task 4).
3. A configuration uses `true` as an integer, duplicates a task, or contains nonfinite weights: reject it before workers, provider calls, or run creation (Tasks 1 and 11).
4. Equivalent optimizers run in a different order, or a previous task consumes extra FakeLLM responses: comparison seeds, populations, and fake responses stay independent (Tasks 6 and 9).
5. The final outer child is best, every candidate fails, or there are zero iterations: evaluate before selection and emit the correct winner or explicit failed status with diagnostic artifacts (Tasks 10–11).

Implementation choices where the spec leaves details open:

- V0 worker process-group handling targets POSIX/Linux. Reject unsupported platforms clearly; do not imply equivalent containment on Windows.
- Use strict Pydantic models at external boundaries and immutable dataclasses for internal records. Do not place a mutable utility on a heuristic or optimizer candidate.
- Run one fresh worker per candidate per instance. This is slower than pooling, but makes state isolation and per-instance deadlines straightforward.
- The worker returns a tour, never an authoritative score. The parent validates and scores it. Use bounded pipes with selectors, not unbounded `communicate()` capture or pickle.
- Outer capacity is a strict integer of at least two because both prescribed seed optimizers must fit. Inner capacity is 2–10. Root seed is a nonnegative strict integer; iteration counts are nonnegative strict integers.
- Initially omit evaluation caching. The spec permits caching only within identical contexts; no cache avoids accidental reuse across providers, seeds, budgets, or task instances.
- Retain failed candidates only below successful candidates when filling a population. If parents are all failed, continue proposals using ranked candidates and allow a later child to recover; report failure only if no successful final result exists.
- Use a typed, generic call observer to record provider metadata and usage. Provider exceptions are converted to `GenerationError` by the adapter; generation orchestrators catch only expected generation/parse failures. Filesystem and parent programming errors propagate.
